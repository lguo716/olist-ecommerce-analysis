## 4. 为什么三个维度不能使用同一种粒度

### 品类

一笔订单可能包含多个商品，多个商品又可能属于不同品类。品类金额必须来自商品明细的`price`：

```text
先得到一行 = 一个品类在一笔订单中的商品汇总
再得到一行 = 一个品类
```

如果直接把整笔订单金额连接到每个品类，同一订单的金额会在多个品类中重复。

### 商家

一笔订单可能包含同一商家的多个商品，也可能包含多个商家：

```text
先得到一行 = 一名商家在一笔订单中的商品汇总
再得到一行 = 一名商家
```

这样同一商家在同一订单中的多个商品只会贡献一次订单级评分和配送状态。

### 州

订单模型已经一单一行，可以直接按`customer_state`汇总：

```text
一行 = 一个顾客收货州
```

这里的州是顾客收货地址所在州，不是商家注册地址。

## 5. 成交额为什么必须对账

三个维度虽然粒度不同，但成交商品金额最终都应等于平台成交GMV：

| 汇总维度 | 成交额合计 |
|---|---:|
| 平台成交订单 | 13,221,498.11 BRL |
| 品类 | 13,221,498.11 BRL |
| 商家 | 13,221,498.11 BRL |
| 顾客州 | 13,221,498.11 BRL |

品类和商家订单数不能直接相加与平台订单数对账，因为多品类或多商家订单会同时归属于多个分组；商品金额按商品行分配后则必须守恒。

## 6. 缺失品类怎样处理

商品没有品类时仍然发生了真实交易，所以不能删除商品金额：

```python
item_detail["category"] = item_detail["category"].fillna("unknown")
```

`unknown`会作为一个正式诊断分组保留。这样既不会丢失成交额，也能看到缺失品类本身的规模和质量表现。

## 7. 修正低评分率分母

正确公式为：

```text
低评分率
= 订单级评分小于等于2的订单数
÷ 有评分订单数
```

缺失评分表示顾客没有留下有效评分，不能当成“非低评分”。因此三个维度都保留：

| 字段 | 含义 |
|---|---|
| `reviewed_orders` | 有订单级评分的订单数 |
| `low_review_orders` | 订单级评分小于等于2的订单数 |
| `low_review_rate` | 两者相除 |

例如商家`1ca7077d…`：

```text
成交订单：108笔
有评分订单：107笔
低评分订单：64笔

正确低评分率 = 64 ÷ 107 = 59.81%
错误分母结果 = 64 ÷ 108 = 59.26%
```

差异虽然不大，但所有维度必须使用统一口径。

## 9. 品类经营象限

订单太少的品类平均值容易波动，所以只有至少300笔成交订单的品类进入象限比较。

当前结果：

```text
全部品类：74个
达到300单门槛：32个
```

在可靠样本中计算成交额和平均评分中位数，再划分：

```text
高成交额 / 高评分
高成交额 / 低评分
低成交额 / 高评分
低成交额 / 低评分
```

这里的“高”和“低”是相对于当前可靠品类的中位数，不是行业统一标准。

## 10. 为什么使用同期比较

2018年1—8月不能与2017全年直接比较，否则2017多出四个月。项目使用：

```text
2017年1—8月
对比
2018年1—8月
```

计算：

```text
成交额增长率 = 2018同期成交额 ÷ 2017同期成交额 - 1
评分变化 = 2018同期平均评分 - 2017同期平均评分
延迟率变化 = 2018同期延迟率 - 2017同期延迟率
```

两个期间分别至少100笔成交订单，才进入增长质量比较。当前有28个可比品类。

## 14. 为什么商家清单不能直接用于处罚

评价和实际送达时间都记录在订单层。一笔多商家订单只有一个订单级评分，无法知道顾客具体评价哪一个商家。

因此多商家订单的评分会出现在每个参与商家的诊断记录中。关注清单适合用于：

- 查看商家的商品和品类结构；
- 检查是否集中在高延迟地区；
- 下钻多商家订单；
- 联系运营或物流团队复核。

它不是对单个商家责任的最终判定。

## 15. SQL如何表达相同逻辑

SQL同样需要先建立品类—订单或商家—订单中间表：

```sql
GROUP BY category, order_id
GROUP BY seller_id, order_id
```

评分分母使用条件聚合：

```sql
SUM(review_score IS NOT NULL) AS reviewed_orders,
SUM(review_score <= 2) AS low_review_orders,
AVG(CASE WHEN review_score IS NOT NULL THEN review_score <= 2 END)
    AS low_review_rate
```

完整查询位于`sql/06_commercial_diagnostics.sql`。SQL用于复核诊断表，本阶段不连接MySQL执行。
