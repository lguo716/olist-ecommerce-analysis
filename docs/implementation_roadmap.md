# 10 天个人实施路线

这份路线用于自己重新完成关键步骤，而不是直接复制最终结果。每天结束时都记录：解决的业务问题、使用字段与口径、主要结果、限制以及真实业务中的下一步验证。

| 天数 | 核心任务 | 当天必须交付 |
|---|---|---|
| 第 1 天 | 阅读 9 张表、识别主键和连接关系 | 数据字典、关系图、业务问题 |
| 第 2 天 | 导入 MySQL，检查行列数、主键、缺失、孤儿记录和时间逻辑 | 数据质量报告 |
| 第 3 天 | 分别聚合商品、支付和评价，建立一单一行模型 | 订单宽表与金额守恒校验 |
| 第 4 天 | 编写经营 KPI 和完整月份趋势查询 | KPI 汇总、月度趋势 |
| 第 5 天 | 完成总体复购、90 天复购和 RFM | 顾客分层与首单体验诊断 |
| 第 6 天 | 建立首购月份同期群 | 留存明细和热力图 |
| 第 7 天 | 比较准时与延迟订单评分 | 效应差、置信区间、非参数检验 |
| 第 8 天 | 诊断品类、州和商家 | 三张经营诊断表与关注清单 |
| 第 9 天 | 按搭建清单制作 Power BI 四页看板 | `.pbix`、四页截图、数字核对 |
| 第 10 天 | 撰写 README、报告、简历和面试讲解 | 完整作品集 |

## 最低完成标准

- 能解释为什么一对多表必须先聚合。
- 能从 SQL 重新得到核心校验数字。
- 能解释 `customer_id` 与 `customer_unique_id` 的区别。
- 能说明总体复购率与 90 天复购率的观察窗口差异。
- 能解释统计显著、效应量和因果结论的区别。
- Power BI 卡片与 Python/SQL 汇总数字一致。
