# 学习阶段9：Power BI四页经营看板

## 1. 本阶段整体要做什么

前八个阶段已经完成了数据检查、订单模型和专项分析。本阶段不重新发明指标，而是把这些结果组织成管理者可以使用的四页看板：

```text
已验证的CSV输入
→ Power BI数据类型
→ 星型模型关系
→ DAX动态指标
→ 四页经营看板
→ 筛选和下钻
→ 数字对账
→ 保存PBIX与页面截图
```

四页分别回答：

1. 经营总览：平台成交规模和月度变化如何？
2. 用户与复购：顾客是否再次购买，哪些顾客值得维护？
3. 物流与满意度：延迟是否集中在特定州或商家，并伴随低评分？
4. 品类与商家：规模、增长和质量问题集中在哪里？

本阶段完成后，不仅要会摆放图表，还要能解释数据从哪张表来、为什么建立或不建立关系、筛选器如何改变指标，以及为什么品类GMV不能使用整笔订单金额。

## 3. Power BI中三个区域分别做什么

Power BI Desktop可以理解为三层：

```text
Power Query：数据进入模型之前，确认列名和数据类型
模型视图：建立表之间的关系，决定筛选如何传播
报表视图：使用字段和度量值制作卡片、图表、矩阵和切片器
```

三者的顺序很重要。关系建错后，图表即使看起来正常，金额也可能重复；指标口径错误后，图表做得再漂亮也没有意义。

## 6. 11张输入表怎样分工

### 需要建立关系的三张明细表

| 表 | 一行代表什么 | 主要用途 |
|---|---|---|
| `powerbi_orders` | 一笔订单 | 平台KPI、日期趋势、顾客州、物流与评分 |
| `powerbi_order_items` | 一笔订单中的一个商品行 | 品类、商家、商品价格、重量、体积和运费 |
| `powerbi_customers` | 一名成交顾客 | RFM、购买频次、90天复购 |

### 保持独立的八张汇总表

| 表 | 用途 |
|---|---|
| `monthly_metrics` | 新客与复购顾客月度趋势 |
| `cohort_retention_tidy` | 同期群留存矩阵 |
| `category_performance` | 品类规模、评分、延迟率和运费率 |
| `category_growth_quality` | 品类同期增长和质量变化 |
| `seller_scorecard` | 商家经营和履约关注清单 |
| `state_performance` | 州级经营和履约诊断 |
| `repurchase_by_first_delivery` | 首单配送体验与90天复购 |
| `repurchase_by_first_review` | 首单评分与90天复购 |

独立汇总表已经是一行一个分析对象。如果强行把它们与订单明细连接，很容易出现多对多关系，使筛选传播难以控制。它们直接用于对应的视觉对象即可。

## 7. 导入11张CSV

打开Power BI Desktop后：

1. 点击“主页 → 获取数据 → 文本/CSV”；
2. 选择第一张CSV；
3. 预览时点击“转换数据”，进入Power Query；
4. 按`powerbi/build_checklist.md`中的顺序继续导入其余10张；
5. 保留文件名去掉`.csv`后的表名；
6. 核对右下角或状态栏显示的行数；
7. 检查数据类型，完成后点击“关闭并应用”。

最重要的数据类型：

- `purchase_date`必须是“日期”，这样才能和日期表连接；
- 金额、评分、天数和比例为“小数”；
- 订单数、顾客数、件数和`cohort_index`为“整数”；
- `is_late`、`eligible_90d`和样本门槛字段为“True/False”；
- ID字段保持“文本”，不能转换成数字。

ID不是用来计算大小的数值。把ID转换成数字可能丢失前导零，也可能导致导入错误。

## 8. 为什么要建立日期表

订单表虽然有购买日期，但专门的`Date`表可以提供连续日期、年月、季度和规范排序，也使时间筛选和同比、环比计算更稳定。

操作：

1. 点击“建模 → 新建表”；
2. 从`powerbi/date_table.dax`复制`Date = ...`完整公式；
3. 将`Date`标记为日期表；
4. 用`Year Month Sort`排序`Year Month`。

日期表中的`Is Complete Core Month`用于月度趋势图，只保留2017-01至2018-08完整月份。它不作为默认页面筛选，因此页面卡片在无筛选时仍显示全数据验收值。

## 9. 三条关系怎样理解

模型中只建立：

```text
Date                      1 ──── * powerbi_orders
powerbi_customers         1 ──── * powerbi_orders
powerbi_orders            1 ──── * powerbi_order_items
```

三条关系都使用单向筛选。

### 日期到订单

选择某个日期后，订单表只保留该日期范围内的订单，订单KPI随之变化。

### 顾客到订单

选择一名顾客或某个顾客分层时，可以筛选出其订单。顾客表的`customer_unique_id`一人一行，因此位于关系的“一端”。

### 订单到商品

一笔订单可以有多个商品行，所以订单是一端，商品是多端。日期、顾客州和订单状态可以先筛选订单，再向下筛选商品明细。

这里不能使用双向关系。若商品品类反向筛选订单表，某个多品类订单的整单`item_revenue`可能被带入每个品类，造成重复归属。

## 10. 为什么平台GMV和品类GMV使用不同字段

平台卡片：

```text
SUM(powerbi_orders[item_revenue])
```

因为订单表一单一行，每笔订单金额只出现一次。

品类图：

```text
SUM(powerbi_order_items[price])
```

因为商品表一行一个商品行，金额可以准确归属到品类。两种口径最终都应与13,221,498.11 BRL成交GMV对账，但不能在品类视觉中互换。

## 11. DAX度量值是什么

CSV中的列是已经存储的数据；DAX度量值是在当前筛选上下文中即时计算的结果。

例如选择顾客州`RJ`后：

- `[Delivered GMV]`重新计算RJ成交订单金额；
- `[Purchasing Customers]`重新计算RJ成交顾客数；
- `[Repeat Customers]`重新判断当前筛选范围内完成至少两单的顾客；
- `[Low-review Rate]`只用当前筛选范围内有评分成交订单作分母。

这就是“动态指标”。如果直接把顾客表行数写成购买顾客数，它不会正确响应订单日期或州筛选。

`powerbi/measures.dax`已经修正：

- 购买顾客从当前成交订单动态去重；
- 复购顾客按当前筛选范围内的成交订单数动态判断；
- 低评分订单明确排除空白评分；
- 补充延迟订单、延迟率和运费率；
- 增加配送中文标签和商家延迟风险分组计算列。

## 12. 页面1：经营总览

### 页面目的

管理者首先需要看到“规模、顾客和履约”三类总体状态，再从月份、品类和州下钻。

### 页面结构

```text
标题 + 日期/州/状态筛选器
6张KPI卡片
月度GMV与订单量 | Top 10品类 | 州级经营矩阵
```

六张卡片使用成交GMV、成交订单、客单价、购买顾客、复购率和准时率。月度组合图给GMV和订单量不同坐标轴，避免两个量级相差太大。

月度图的视觉级筛选设置`Date[Is Complete Core Month] = True`。默认日期切片器保持清空，因此全量卡片应显示验收基准；用户主动选择日期后，卡片和明细图再响应筛选。

## 13. 页面2：用户与复购

### 页面目的

区分三个不同问题：

- 总体复购率：整个数据窗口内是否买过至少两次；
- 90天复购率：拥有完整90天观察机会的人是否在90天内再买；
- 同期群留存：不同首购月份的顾客在之后每个自然月是否再次活跃。

本页不放日期切片器。因为90天复购、RFM和同期群均依赖固定观察窗口，随意切日期会改变分母，却仍显示原有汇总表结果，造成口径混合。

同期群矩阵：

- 行：`cohort_month`；
- 列：`cohort_index`；
- 值：`retention_rate`；
- 条件格式：数值越高颜色越深；
- 第0月必须全部为100%。

## 14. 页面3：物流与满意度

### 页面目的

展示平台履约总体水平，并回答延迟订单是否同时出现明显更高的低评分率。

准时和延迟对比使用同一张订单表与动态度量。筛掉配送信息缺失，颜色固定为：

- 准时：蓝色`#2563EB`；
- 延迟：红色`#DC2626`。

全量基准：

| 指标 | 延迟 | 准时 |
|---|---:|---:|
| 有配送判断且有评分订单 | 7,661 | 88,163 |
| 低评分率 | 53.99% | 9.19% |

州矩阵只显示`reliable_sample=True`；商家表只显示至少30笔成交订单的可靠样本。这样小样本极端比例不会自动排在最前面。

## 15. 页面4：品类与商家

### 页面目的

将规模、增长和质量放在同一页，不把“卖得多”直接解释为“经营健康”。

品类矩阵只比较至少300笔成交订单的品类。品类增长散点图只显示2017年1—8月和2018年1—8月各至少100单的可比品类。

散点图解释：

```text
越靠右：成交额增长越快
越靠上：评分改善越明显
点越大：成交额规模越大
风险颜色：增长同时伴随评分下降或延迟率恶化
```

商家象限只使用至少30单的商家。横轴为成交额，纵轴为平均评分，点大小表示订单数，延迟风险分组控制颜色。

商品运费散点图以品类作为明细点，比较平均重量与平均运费，并将体积放入工具提示。这样只有约74个点，避免把十多万商品行全部绘制后难以阅读。

## 16. 筛选、交互与下钻

切片器本质上是向模型发送筛选条件。建立一个切片器后，用“格式 → 编辑交互”检查每个视觉右上角：

- 漏斗图标：该视觉接受筛选；
- 禁止图标：该视觉不受此切片器影响。

经营总览的日期、州和状态应影响订单与商品明细视觉。独立汇总表之间没有关系，因此不能期望一个订单表切片器自动过滤同期群或商家汇总表。

下钻适合明确的层级，例如“州 → 商家”或“品类 → 商家”。下钻不是建立关系的替代品，字段必须来自能够共同解释同一视觉的数据表。

## 17. 四个搭建检查点

实际操作按小步核对：

1. 导入完成：发模型字段和行数截图，核对11张表；
2. 关系完成：发模型视图截图，核对三条单向关系；
3. DAX完成：发临时验收卡片截图，核对九个核心数字；
4. 每完成一页：发页面截图，逐页核对字段、筛选、颜色和数字。

这样一旦数字异常，可以确定问题发生在导入、关系、DAX还是视觉设置，而不需要在四页全部做完后重新排查。
