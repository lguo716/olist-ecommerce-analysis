## 4. 第一步：确定分析样本

本阶段只分析已经送达的订单：

```python
delivered = order_model[order_model["is_delivered"]]
```

比较物流状态和评分时，一笔订单必须同时满足：

1. 有实际送达时间；
2. 有预计送达时间；
3. 有评分。

```python
analysis = delivered[
    delivered["is_late"].notna()
    & delivered["review_score"].notna()
]
```

样本筛选结果：

| 步骤 | 订单数 |
|---|---:|
| 成交订单 | 96,478 |
| 有完整实际和预计送达时间 | 96,470 |
| 有评分 | 95,832 |
| 同时有配送判断和评分 | 95,824 |

缺少配送判断的8笔订单和缺评分的646笔订单没有重叠。因此最终样本为：

```text
96,478 - 8 - 646 = 95,824
```

缺失评分不能填成0分，因为“顾客没有评分”与“顾客给出最低评分”是完全不同的业务行为。

## 5. 第二步：理解三个关键字段

### 履约时长

```text
delivery_days
= 实际送达时间 - 下单时间
```

它回答顾客下单后经过多少天收到商品。

### 配送偏差天数

```text
delivery_delta_days
= 实际送达时间 - 预计送达时间
```

- 大于0：晚于预计日期送达；
- 等于0：预计日期当天送达；
- 小于0：早于预计日期送达。

负值表示提前送达，不是数据错误。

### 延迟状态

```python
is_late = delivery_delta_days > 0
```

预计日期当天或之前送达都归为准时。

## 6. 时间警告为什么不影响本阶段

第二阶段发现：

- 166笔交给承运商时间早于下单；
- 23笔收货时间早于交给承运商。

这些异常涉及`order_delivered_carrier_date`。本阶段使用的是：

- 下单时间到实际收货时间；
- 预计收货时间到实际收货时间。

两项公式都不使用承运商接货时间。因此这些订单仍可用于本阶段；将来分析“承运商接货到顾客收货”的时长时，才需要排除相关异常记录。

## 7. 第三步：定义低评分

Olist原始评价分数范围为1至5分。同一订单可能存在多条评价，订单模型先取这些评价的平均分，因此分析样本中有116笔订单的订单级评分为1.5、2.5等小数。

本项目按订单级平均评分定义：

```text
小于或等于2分 → 低评分
大于2且小于4分 → 中等评分
大于或等于4分 → 高评分
```

低评分率为：

```text
低评分订单数 ÷ 有评分订单数
```

本阶段两组样本都已经筛选为有评分订单，因此不会把缺失评分放入分母。

## 8. 第四步：比较准时与延迟订单

| 指标 | 延迟订单 | 准时订单 |
|---|---:|---:|
| 订单数 | 7,661 | 88,163 |
| 平均评分 | 2.57 | 4.29 |
| 评分中位数 | 2 | 5 |
| 低评分订单 | 4,136 | 8,100 |
| 低评分率 | 53.99% | 9.19% |
| 平均履约时长 | 31.38天 | 10.88天 |
| 平均配送偏差 | 延迟9.45天 | 提前13.01天 |

平均数说明整体水平，中位数说明排序后位于中间的评分。两种指标都显示延迟组的评分明显更低。

## 9. 第五步：计算业务效应大小

### 百分点差

```text
53.99% - 9.19% = 44.80个百分点
```

这是两组低评分率的绝对差异。

### 风险比

```text
53.99% ÷ 9.19% = 5.88倍
```

在当前观察样本中，延迟订单出现低评分的比例约为准时订单的5.88倍。

### 平均评分差

```text
2.57 - 4.29 = -1.73分
```

负数表示延迟组评分更低。

这些指标回答“差异有多大”。p值不能代替效应大小。

## 10. Welch 95%置信区间

两组评分数量和方差不完全相同，因此项目使用Welch方法计算平均评分差的标准误和自由度。

结果为：

```text
延迟组平均评分 - 准时组平均评分 = -1.7278
95%置信区间 = [-1.7657, -1.6899]
```

整个区间都低于0，说明在当前抽样假设下，延迟组平均评分较低这一方向非常稳定。

置信区间同时提供差异方向、差异大小和估计精度，比只报告“显著”包含更多信息。

## 11. 为什么使用Mann–Whitney U

原始评分只有1至5五个等级；少数订单聚合多条评价后会产生小数，但评分仍然有序、取值有限，而且大量订单集中在1分和5分，不符合普通连续正态数据的形态。

Mann–Whitney U检验比较两组订单级评分的整体排序和分布：

```text
U = 150,680,825.5
p < 1e-300
```

这表示两组评分分布差异非常难用随机样本波动解释。

程序得到的原始p值为`0.0`，这是浮点数精度下溢，不代表真实概率绝对等于0，因此报告中写作`p < 1e-300`。

## 12. Spearman相关回答什么

Spearman使用数据排序，衡量两个变量是否呈稳定的单调关系。本项目比较：

```text
delivery_delta_days 与 review_score
```

结果：

```text
Spearman ρ = -0.1757
p < 1e-300
```

负号表示配送相对预计日期越晚，评分总体越低。绝对值约0.176，属于较弱的整体排序关系。

## 13. 为什么组间差异很大，相关系数却较弱

两项分析使用不同视角：

- 准时/延迟分组只关注订单是否越过预计日期这个业务阈值；
- Spearman使用全部提前或延迟天数的排序，检查是否“每晚一些，评分就持续下降”。

可能出现大量提前不同天数的订单都给5分，也可能有延迟程度相近但评分不同的订单。因此延迟组与准时组的平均差异可以很大，而所有订单上的单调相关仍然较弱。

## 14. 统计显著、业务差异和因果关系

三个概念要分开：

| 概念 | 本阶段怎样判断 |
|---|---|
| 统计显著 | p值和置信区间显示差异不是普通随机波动 |
| 业务差异 | 评分低1.73分、低评分率高44.80个百分点、风险比5.88倍 |
| 因果关系 | 当前观察数据不能单独排除商品质量、商家服务、地区和品类等因素 |

因此可以说“延迟订单伴随更差评分”，不能只根据当前分析写成“延迟是所有低评分的唯一原因”。

## 15. SQL如何复核分组汇总

SQL使用`CASE WHEN`划分配送组：

```sql
CASE
    WHEN order_delivered_customer_date <= order_estimated_delivery_date
        THEN 'On time'
    ELSE 'Late'
END AS delivery_status
```

再使用`COUNT`、`AVG`和条件表达式计算订单数、平均评分、低评分率和履约时间。完整查询位于`sql/03_business_metrics.sql`。

SQL适合复核描述统计；Welch置信区间、Mann–Whitney U和Spearman相关继续在Python中完成。
